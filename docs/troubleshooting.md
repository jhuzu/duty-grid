# 疑難排解

## 開發版無法啟動

先在根目錄執行：

```sh
pnpm install
pnpm test
pnpm tauri:dev
```

Vite 固定使用連接埠 1420，且設定 `strictPort: true`；若該連接埠已被占用，開發版不會自動換埠。停止佔用程序後重試。若 Rust 編譯失敗，確認已安裝可用的 Rust toolchain 與 macOS 的 Tauri 建置需求；專案未提供安裝腳本或最低版本，屬**待確認**。

## 只執行 `pnpm dev` 時資料操作失敗

這只會啟動瀏覽器前端，沒有 Tauri/Rust command。請改用 `pnpm tauri:dev`。

## 地圖空白或地圖輸出失敗

地圖模式需要存取國土測繪中心 WMTS；載入錯誤時程式會改用 OpenStreetMap。兩者皆無法存取時，地圖可能無底圖，且畫布匯出會顯示「地圖尚未完成載入」。確認網路、代理或防火牆允許這兩個服務後重新載入。若不便連網，建立「自選底圖模式」計畫。

## 無法新增或更新點位

建立時必須輸入點位編號與名稱。編輯時經緯度必須在 latitude -90 至 90、longitude -180 至 180；自選底圖的 XY 座標必須介於 0–1000。點位類型只支援勤務、空心圓、號誌；更新顏色只支援紅、橘、黃、綠、藍、紫。

刪除點位失敗時，先刪除使用它的勤務路線。路線停靠點的外鍵設定為 `ON DELETE RESTRICT`，會阻止刪除仍被參照的點位。

## 人員資料沒有匯入或部分被拒絕

確認檔案為 `.csv` 或 `.xlsx`，且前十列之一具有六個必要欄位。CSV 可用 UTF-8/BOM 或 Big5，含逗號的欄位請以雙引號包住。介面「最近匯入」會列出拒絕列和原因。常見原因為必填欄位空白，或員編和無線電代號分別對應到兩位既有人員。

匯入會更新相同員編或無線電代號的既有資料，不是只新增；匯入前請保留來源檔案備份。

## 無法匯出 Excel

選擇一條包含點位的勤務路線，並確認部署表最多 33 列。程式固定填入 Excel 範本的 `sheet1`、A7:I39；若範本被替換或該工作表/儲存格不存在，會回報「範本缺少儲存格」或讀取範本失敗。正式打包版本需包含 `resources/standard_deployment_template.xlsx`；開發環境則會退回專案根目錄的 `標準化部署表.xlsx`。

## 工作區設定在重啟後消失

目前版本會在開啟勤務計畫時還原資料庫中的工作區狀態。若需要在另一台電腦或重建資料庫後繼續工作，仍請使用「儲存工作區」建立 `.dutygrid-workspace.json`，並在「勤務計畫」頁以「開啟工作區」選取它。此檔不是完整資料庫備份，無法取代備份 `dutygrid.db`。

## 想備份或移轉資料

先關閉應用程式，再備份 app local data 目錄中的 `dutygrid.db` 與 `custom-basemaps/`。具體 macOS 路徑未由程式顯示，請依 bundle identifier 在系統應用程式資料目錄查找；正式與開發版目錄不同。移轉前請在副本上測試，因資料庫升級會自動套用 migration，且沒有內建降版工具。

## 回報問題時應附上什麼

請附上執行的指令、完整錯誤文字、是否使用地圖或自選底圖模式、輸入檔格式與欄位標題，以及不含個資的最小重現步驟。不要上傳真實人員資料、電話或未去識別化的資料庫。
